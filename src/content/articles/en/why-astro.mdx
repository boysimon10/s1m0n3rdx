## The default should be no JavaScript

Every framework I looked at ships JavaScript first and asks you to opt out. Astro does the opposite - zero JS by default, opt in with `client:*` directives when you actually need it.

For a blog, that's the right default. A post is text. It doesn't need a hydrated React tree.

## Islands

The islands model is the part that sold me. You can mix a fully static page with one interactive component (a search bar, a demo widget) without shipping a full SPA runtime for the whole page.

```astro
<!-- Static everywhere except here -->
<SearchWidget client:idle />
```

`client:idle` means it hydrates after the page is interactive. `client:visible` means it waits until it scrolls into view. These are thoughtful defaults.

## MDX + Content Collections

MDX lets me drop components into posts when I need them. Content Collections give type-safe frontmatter with Zod - no more undefined field bugs.

```ts
const blog = defineCollection({
  schema: z.object({
    title: z.string(),
    date: z.coerce.date(),
    tags: z.array(z.string()).default([]),
  }),
});
```

TypeScript knows the shape of every post at build time.

## What I gave up

No built-in server-side rendering per request without an adapter. For a personal site that's fine - `output: 'static'` + Cloudflare Pages is fast and free.

If I needed auth or dynamic user data I'd reconsider. But I don't.
