## Pourquoi Go pour un CLI

Go compile en un seul binaire statique. Pas de runtime à installer, pas de dépendances à gérer côté utilisateur — tu distribues un exécutable, c'est tout. Pour un outil CLI, c'est l'argument qui clôt le débat.

## Structure du projet

```
cmd/
  root.go
  build.go
internal/
  config/
  runner/
main.go
```

La règle : tout ce qui est dans `internal/` n'est pas exporté hors du module. `cmd/` contient uniquement la définition des commandes cobra, sans logique métier.

## Cobra en pratique

```go
var rootCmd = &cobra.Command{
  Use:   "mycli",
  Short: "Mon outil de dev",
}

func init() {
  rootCmd.AddCommand(buildCmd)
  rootCmd.AddCommand(deployCmd)
}
```

## Distribution

```yaml
# .github/workflows/release.yml
- uses: goreleaser/goreleaser-action@v5
```

GoReleaser construit les binaires pour Linux, macOS et Windows en une commande, et pousse les assets sur GitHub Releases.
