## Le contexte

J'ai démarré avec React Native parce que je venais du web React. La transition semblait naturelle — mêmes patterns, même logique de composants, même écosystème npm.

Puis un client m'a imposé Flutter sur un projet. J'ai résisté, appris Dart en deux semaines, livré le projet, et changé d'avis sur plusieurs points.

## Ce que Flutter fait mieux

**Cohérence visuelle.** Le rendu est identique sur iOS et Android parce que Flutter dessine ses propres widgets. Pour des apps avec un design system fort, c'est un avantage énorme.

**Performance perçue.** Pas d'overhead de bridge JavaScript. Les animations à 60fps sont plus faciles à tenir.

## Ce que React Native fait mieux

**L'écosystème.** npm > pub.dev pour l'instant. Si t'as besoin d'une intégration tierce, la lib existe probablement déjà.

**Le partage de code avec le web.** Avec Expo et une monorepo bien structurée, partager la logique métier entre web et mobile est réel.

## Mon choix aujourd'hui

React Native + Expo pour 90% des projets. Le DX s'est énormément amélioré ces deux dernières années. Flutter quand le client a des exigences de design très poussées ou que les performances sont critiques.
